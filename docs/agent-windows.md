Агент устанавливается непосредственно на каждый сервер 1С и сам подключается к `oneswiss-server`. Перед установкой агентов необходимо развернуть серверную часть и убедиться, что ее адрес доступен с хоста 1С.

## Скачивание архива

Для Windows доступна только сборка **x64**. Архив агента необходимо скачать из вложений релиза и распаковать все файлы в выбранную папку. Далее в инструкции для примера используется `C:\oneswiss-agent`. Если для агента выбран другой путь, необходимо заменить его во всех командах примера. Служба будет запускать агент из выбранной папки, поэтому после установки нельзя ее  перемещать или удалять.

## Настройка подключения

В папке агента необходимо отредактировать файл настроек `appsettings.json`. В примере используется встроенная аутентификация OneSwiss.
Секреты для агентов создаются в веб-панели под администратором **"Общее" - "Секреты агентов"**. Значения `ClientId` и `ClientSecret` необходимо указать в файле конфигурации.

Пример файла `appsettings.json`:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.Hosting.Lifetime": "Information",
      "Microsoft.EntityFrameworkCore.Database": "Warning",
      "OneSwiss.Agent.Services.CommandsWatcher": "Trace"
    }
  },
  "InstanceName": "",
  "Server": "wss://api.oneswiss.example.com",
  "Auth": {
    "Required": true,
    "TokensEndpoint": "https://api.oneswiss.example.com/api/auth/token",
    "ClientId": "CLIENT_ID_FROM_WEB_PANEL",
    "ClientSecret": "CLIENT_SECRET_FROM_WEB_PANEL"
  },
  "TechLogFolder": "", 
  "V8": {
    "PlatformPaths": [

    ]
  }
}
```

Можно заменить содержимое файла этим JSON, подставив адрес своего сервера и выданные `ClientId` и `ClientSecret`. `InstanceName`, `TechLogFolder` и `V8.PlatformPaths` можно оставить пустыми, как в примере: будут использованы значения и пути по умолчанию.

**Параметры файла**:

- InstanceName - наименование агента, отображаемое в веб-панели. Если не задано - то агент автоматически возьмет имя машины, на которой запущен
- Server - адрес и порт, по которым агент будет обращаться к серверной части, (`PUBLIC_BACKEND_URL` в `docker-compose.yml`) . Если сервер опубликован по https, то для доступа агентов необходимо использовать wss, а не ws
- Auth
  - Required - флаг необходимости получения и использования jwt токена для аутентификации агента при подключении к серверу oneswiss
  - TokensEndpoint - адрес конечной точки издателя токенов аутентификации (`client_credentials` grant, OAuth2). Это может быть:
    - внешний OIDC/SSO провайдер (например, `https://sso.example.com/protocol/openid-connect/token`) - в этом случае сервер oneswiss должен быть настроен в режиме `Auth__Mode=Mixed` с `Auth__Jwt__SigningKey` не заданным (пустым) - иначе сервер не примет токены от внешнего провайдера;
    - Встроенная аутентификация OneSwiss - агент получает токен серверной части OneSwiss. В `TokensEndpoint` необходимо указать адрес API с добавлением `/api/auth/token`: например, `https://api.oneswiss.example.com/api/auth/token`. Если API доступен по HTTP без HTTPS, используйте адрес вида `http://192.168.1.10:7002/api/auth/token`.
  - ClientId - идентификатор клиента
  - ClientSecret - секрет клиента
- PlatformPaths - дополнительные пути, если платформы установлены не в каталогах установки платформы 1С по умолчанию
- TechLogFolder - служебный каталог сбора технологического журнала, используемый в работе подсистемы сеансов сбора ТЖ.
  Если не указан, то используется стандартный путь:
  - Windows - %PROGRAMDATA%/oneswiss/techlog

>💡 В JSON обратные слеши путей нужно писать дважды: например, `C:\\oneswiss-agent\\techlog`.

## Windows: установка службы

Необходимо запустить PowerShell **от имени администратора** Сначала можно запустить агент в консоли, чтобы увидеть возможные ошибки настроек:

```powershell
Set-Location C:\oneswiss-agent
.\oneswiss-agent.exe --contentRoot C:\oneswiss-agent
```

После проверки подключения необходимо завершить процесс сочетанием `Ctrl+C`, зарегистрировать службу и включить автозапуск:

```powershell
New-Service -Name OneSwissAgent -DisplayName 'OneSwiss Agent' -BinaryPathName 'C:\oneswiss-agent\oneswiss-agent.exe --contentRoot C:\oneswiss-agent' -StartupType Automatic
Start-Service OneSwissAgent
Get-Service OneSwissAgent
```

Эта команда создает службу под `LocalSystem`. Доступ на чтение `appsettings.json` необходимо ограничить администраторами и учетной записью службы, поскольку файл содержит секрет.

## Проверка подключения и обновление

После запуска агент должен появиться в веб-панели. Статус службы "работает" сам по себе не подтверждает подключение к серверу.

Для обновления необходимо остановить службу, сохранить резервную копию каталога агента, заменить файлы программы содержимым нового архива для той же ОС и запустить службу.

## Обновление секретов агента

При использовании встроенной аутентификации OneSwiss:

1. В веб-панели под администратором **"Общее" - "Секреты агентов"** и создаем новый секрет. Сразу нужно скопировать выданные `ClientId` и `ClientSecret`: секрет показывается только один раз.
2. В файле `C:\oneswiss-agent\appsettings.json` заменяем значения `Auth.ClientId` и `Auth.ClientSecret` на новые и сохраняем файл.
3. Перезапускаем службу, чтобы агент подключился с новыми учетными данными: 
   1. **«Службы»** (`Win+R` → `services.msc`), в списке нужно найти **OneSwiss Agent** и выбрать **«Перезапустить»** в контекстном меню. Для этого нужны права администратора. 
   2. Также можно выполнить `Restart-Service OneSwissAgent` в PowerShell **от имени администратора**.
4. В веб-панели нужно убедиться что агент снова подключен к серверу.
5. Старый секрет в разделе **"Общее" - "Секреты агентов"** нужно удалить. Если секрет используют несколько агентов, сначала нужно обновить настройки и проверить подключение каждого из них.
